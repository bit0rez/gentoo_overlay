# Работа с Gentoo overlay

Эти инструкции действуют для всего репозитория. Имя overlay — `bit0rez`,
основной репозиторий eclass — `gentoo`. Manifest использует режим
`thin-manifests`, кеш метаданных — формат `md5-dict`.

## Перед началом

- Проверь `git status --short` и сохрани чужие и несвязанные изменения.
- Изучи последний ebuild пакета, его Manifest и файл
  `metadata/md5-cache/<category>/<package-version>`.
- Проверь, какой каталог Portage использует для `bit0rez`:
  `portageq get_repo_path / bit0rez`. Проверки должны использовать текущий
  checkout, даже если Portage настроен на другую копию overlay.

## Обновление пакетов

- Определяй актуальную версию по официальным метаданным upstream.
  Если версия в overlay уже актуальна, проверь её и сообщи об этом.
- Добавляй ebuild новой версии на основе последнего подходящего ebuild.
  Не удаляй старые версии и не меняй зависимости, USE-флаги, keyword'ы или
  лицензии без причины, относящейся к задаче.
- Для бинарных пакетов проверь размер и опубликованную контрольную сумму
  архива, версию, архитектуру и пути, используемые при установке.
- Учитывай изменения структуры архива. Сохраняй необходимые launcher'ы,
  ресурсы и библиотеки; проверяй исполняемые права и ссылки.
- Обновляй Manifest и кеш метаданных вместе с ebuild. Предпочитай штатные
  `ebuild ... manifest` и `egencache --repo bit0rez --update category/package`.
  Для `egencache` явно настрой расположение текущего checkout и сохрани
  репозитории, необходимые системному профилю.
- Скачанные архивы, распакованные файлы, логи и кеши проверок размещай в
  отдельном временном каталоге задачи вне checkout. После завершения удаляй только
  проверенные временные файлы своей задачи.

Официальные источники версий для desktop-пакетов:

- ChatGPT: `https://persistent.oaistatic.com/codex-app-prod/linux/deb/dists/stable/main/binary-amd64/Packages`.
- MAX: `https://download.max.ru/linux/deb/dists/stable/main/binary-amd64/Packages`.
  Полная версия ebuild берётся из имени файла `MAX-<version>.deb`.
- Yandex Music: `https://desktop.app.music.yandex.net/stable/latest-linux.yml`.
  URL архива и контрольную сумму сверяй с актуальными метаданными.

## Проверки

- Запусти `bash -n` для изменённых ebuild и `git diff --check`.
- Запусти `pkgcheck scan` для затронутых пакетов. При необходимости размести
  его кеш через `XDG_CACHE_HOME` во временном каталоге задачи.
- Проверь соответствие Manifest архиву и поля `_md5_` содержимому ebuild.
- Проверь зависимости через `emerge --pretend --verbose --oneshot` с точными
  атомами версий и текущим checkout в `PORTDIR_OVERLAY`.
- Для изменённых desktop-файлов запусти `desktop-file-validate` после
  преобразований, которые выполняет ebuild.
- Отделяй замечания к старым версиям и неподдерживаемым профилям от проблем
  нового ebuild. В частности, ChatGPT требует glibc и не поддерживает musl.
- Если обязательная проверка завершилась ошибкой или недоступна, выясни
  причину и сообщи об ограничении. Не выдавай её за успешную и не публикуй
  изменения до устранения проблемы или явно согласованного исключения.
- Установка, полная сборка и проверка запуска приложения требуют отдельного
  запроса. Статические проверки не подтверждают работоспособность приложения.

## Git и публикация

- Запрос на обновление пакета сам по себе не разрешает коммит, push или
  установку. Выполняй их, когда пользователь явно запросил эти действия.
- Перед коммитом просмотри весь diff. Добавляй файлы в индекс поимённо;
  не используй `git add .` или `git add -A`.
- Если пользователь просит закоммитить всё, включи все текущие изменения
  после просмотра, по-прежнему добавляя файлы поимённо.
- Проверь `git diff --cached --check` и staged diff перед коммитом.
- Перед push проверь текущую ветку, remote и состояние удалённой ветки.
  Не используй force push без явного разрешения.
- После push сравни локальный HEAD с SHA удалённой ветки через
  `git ls-remote` и проверь состояние рабочего дерева.
- В результате укажи версии пакетов, выполненные проверки и их ограничения,
  факт установки и публикации, а при публикации — SHA коммита.
